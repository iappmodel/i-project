# INVENTION_010 — Adaptive Gaze Calibration with Polynomial Residual Model

**Inventor:** Marcelo Silva
**Category:** Patent
**Family:** Attention Verification
**Date:** 2026-06-15

## Problem Solved

Consumer-grade front-facing cameras produce noisy gaze estimates that vary dramatically across device types, user facial geometry, and viewing conditions. Simple offset/scale calibrations fail to capture non-linear distortions inherent in webcam-based eye tracking, resulting in poor accuracy that undermines gaze-driven interaction and attention verification. No existing consumer system combines affine correction with polynomial residual compensation in a device-class-aware profile.

## Current Industry Approach

Most browser-based eye-tracking libraries (WebGazer.js, GazeRecorder) use ridge regression or simple linear mapping from facial landmarks to screen coordinates. Mobile AR frameworks (ARKit, ARCore) provide raw gaze vectors without user-specific residual correction. Research systems use neural-network calibration but require GPU inference unsuitable for real-time mobile use. None combine a lightweight affine fit with a degree-2 polynomial residual model stored as compact 6-coefficient vectors with Tikhonov regularization.

## How [ i ] Solves It

The [ i ] calibration system performs a two-stage correction. First, a 6-parameter affine transform (2×3 matrix) is fitted via least-squares from calibration gaze samples, mapping raw gaze to screen coordinates. Second, the affine-corrected positions are further refined by a degree-2 polynomial residual model (basis: 1, x, y, xy, x², y²) fitted with weighted regularized regression (Tikhonov/ridge, λ=0.05). Each axis gets its own 6-coefficient vector (coeffX, coeffY). The system stores device-class-aware profiles (iPhone, Android, desktop) with distinct runtime presets for gaze scale, smoothing, pointer response, and blink detection parameters. Profile quality is computed from calibration error, mandatory gesture verification (blink, pinch), and optional bonus gestures (double-blink, head nod).

## System Description

The calibration pipeline begins with a user completing a target-following sequence on screen. Each sample records the known target position and the raw gaze estimate. When sufficient samples are collected (minimum 4 for affine, device-class-dependent minimum for residual), `fitAffine()` solves the 3×3 normal equations via Gaussian elimination with partial pivoting to produce 6 affine parameters. After affine correction, residual training samples are generated by computing the distance-weighted error between the affine-corrected position and the true target. `fitResidualModel()` constructs a 6×6 Gram matrix from degree-2 polynomial features [1, x, y, xy, x², y²], adds ridge regularization to the diagonal, and solves for coefficients via Gaussian elimination. The resulting `VisionResidualModel` stores both coefficient vectors, lambda, sample count, MSE, and training timestamp. At runtime, `applyResidualCompensation()` evaluates the polynomial features at the current gaze position and adds the predicted displacement (dot product of coefficients and features) to produce the final corrected coordinate. The `VisionCalibrationProfile` stores all parameters including affine params, residual model, device class, gesture thresholds, and quality score. Device-class-specific runtime presets adjust gaze scale, smoothing, hold time, edge thresholds, and blink detection parameters. The system includes auto-calibration support, local storage persistence, and event-based change notification.

## Data Flow

1. User follows calibration targets on screen; samples collected as (targetX, targetY, gazeX, gazeY)
2. `fitAffine()` computes 6 affine parameters from accumulated samples via normal equations
3. Affine-corrected positions computed for each sample
4. Distance-weighted residual training samples generated (closer to target = higher weight)
5. `fitResidualModel()` fits degree-2 polynomial coefficients with ridge regularization
6. Calibration quality scored from residual MSE + gesture verification
7. Complete `VisionCalibrationProfile` stored to localStorage with device class
8. At runtime, raw gaze → affine correction → residual compensation → final calibrated coordinate
9. Calibrated coordinates feed into `attentionScoring.ts` for attention verification

## User Flow

The user enters calibration mode (prompted on first use or if quality degrades). Five to nine target dots appear sequentially on screen. The user fixates on each target for a device-appropriate hold time (340ms iPhone, 420ms Android, 320ms desktop). After gaze collection, the system prompts for gesture verification (blink and hand pinch are mandatory; double-blink and head nod are optional bonus). The system computes the two-stage calibration, reports quality, and adjusts gesture sensitivity thresholds for users who struggle with mandatory gestures. The entire process takes 15-30 seconds.

## Economic Flow

1. Calibration quality directly gates attention scoring accuracy
2. Higher-quality profiles enable higher-confidence attention verification
3. Higher-confidence sessions earn premium reward rates
4. Users with poor calibration are prompted to recalibrate rather than earning reduced rewards
5. Device-class-aware tuning ensures fair reward opportunities across iPhone, Android, and desktop
6. Auto-calibration reduces friction, keeping users in the earning loop

## Fraud Prevention

- Mandatory gesture verification (blink + pinch) proves liveness during calibration
- Profile quality scoring prevents acceptance of fake/random calibration data
- Minimum sample requirements (4 affine, 4-5 residual) prevent underdetermined spoofing
- Ridge regularization prevents overfitting to adversarial sample patterns
- Device-class enforcement prevents profile transplant between devices
- Distance-weighted training resists outlier injection
- Calibration timestamp enables staleness detection and mandatory recalibration
- Gesture sensitivity auto-adjusts rather than skipping verification

## Unique Elements

1. Two-stage calibration combining affine transform with degree-2 polynomial residual compensation, each stored as compact 6-coefficient vectors
2. Tikhonov-regularized weighted polynomial regression for residual correction with distance-based sample weighting
3. Device-class-aware calibration profiles with distinct runtime presets for iPhone, Android, and desktop
4. Integrated gesture verification (blink, pinch, double-blink, head nod) as part of calibration quality scoring
5. Adaptive gesture sensitivity reduction for users who fail mandatory gestures, lowering thresholds rather than skipping verification
6. Profile quality metric combining calibration MSE, mandatory gesture score, and optional bonus gesture score into a single [0,1] value
7. Polynomial basis [1, x, y, xy, x², y²] capturing both linear residuals and quadratic/cross-term non-linearities from lens distortion

## Potential Patent Claims

1. A method for calibrating gaze estimation on a consumer device comprising: fitting a 6-parameter affine transform from user gaze samples via least-squares; computing residual errors from the affine-corrected positions; fitting a degree-2 polynomial residual model with ridge regularization using distance-weighted training samples; and combining both models at runtime to produce a corrected gaze coordinate.

2. A computer-implemented gaze calibration system comprising: device-class-aware calibration profiles storing distinct runtime parameters for each device category; a two-stage correction pipeline including affine and polynomial residual stages; and integrated liveness verification via gesture detection as a mandatory component of calibration quality scoring.

3. A method for adaptive gaze calibration comprising: collecting gaze-target sample pairs during a user-facing calibration session; solving a regularized polynomial system to produce per-axis 6-coefficient residual vectors; computing a composite profile quality score from calibration error and gesture verification results; and adjusting gesture detection sensitivity thresholds based on user performance without eliminating verification requirements.

4. A system for cross-device gaze calibration comprising: detecting a device class from user agent characteristics; selecting device-specific capture timing, smoothing, and sensitivity presets; fitting an affine transform followed by a polynomial residual model to user calibration data; persisting the complete calibration profile to local storage; and applying the two-stage correction in real-time to raw gaze estimates for attention scoring.
